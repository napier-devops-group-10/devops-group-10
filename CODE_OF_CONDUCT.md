# Team Code of Conduct — DevOps Group 10
**Module:** SET09803 DevOps  
**Project:** Population Reporting System  

---

## 1. Purpose & Scope
We are working as a 3-person agile Scrum team to deliver the DevOps coursework. This document establishes our mutual agreements, standards of communication, and disciplinary procedures for the project lifecycle.

---

## 2. Core Expectations

### Attendance & Meetings
* **Stand-ups & Sprints:** All 3 members must attend agreed virtual or in-person team meetings.
* **Advance Notice:** If unable to attend a team session due to illness, work, or emergencies, give at least 24 hours' advance notice in the group chat.
* **Code Reviews:** All 3 members must attend the graded module Code Reviews (Week 6/7 and Week 12/13) at the university's allocated time slots.

### Communication & Collaboration
* Treat team members with respect, patience, and professional courtesy.
* Use our shared messaging channel for daily updates, questions, and blockers.
* Raise roadblocks immediately rather than waiting for sprint deadlines.

### GitFlow & Development Rules
* **Equal Distribution:** Work packages and user stories will be distributed equitably among all 3 members across both assessment points.
* **Branch Protection:** No direct commits to `master` or `develop`. All work must be completed on feature branches.
* **Pull Requests:** Every pull request into `develop` requires review and sign-off from at least one other team member.
* **Build Integrity:** Code must compile cleanly with Maven and pass automated continuous integration checks on GitHub Actions before merging.

---

## 3. Contribution Tracking & Peer Assessment
* In line with module assessment criteria, the team will submit a single agreed contribution spreadsheet for Code Review 1 and Code Review 2.
* Marks will be allocated across the 3 members, strictly totalling 100% at each assessment point (target baseline: ~33.3% each).
* Individual ratings will be supported by concrete project metrics:
  1. Completion of assigned Zube / GitHub issues and user stories.
  2. GitHub commit frequency, pull requests, and review participation.
  3. Punctuality and attendance at team meetings and official code reviews.
* If a consensus cannot be reached, the metrics recorded on GitHub will be submitted directly to the module leader for evaluation.

---

## 4. Conflict Resolution & Disciplinary Escalation
If any member fails to engage, misses milestones without valid mitigation, or does not complete assigned tasks:

1. **Informal Discussion:** The team holds a direct, supportive discussion with the individual to clarify expectations and offer assistance.
2. **Formal Written Notice:** If the issue persists after 5 working days, a formal written notice will be sent outlining missed deliverables and required recovery actions.
3. **Escalation to Module Leader:** Continued failure to contribute will be reported directly to Kevin Sim with supporting evidence (chat records, meeting logs, and GitHub contribution graphs). Following university policy, dismissal from the group results in failing the coursework.
